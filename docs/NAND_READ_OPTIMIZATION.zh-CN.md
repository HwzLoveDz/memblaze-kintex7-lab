# 单颗 NAND 读取提速记录

我在这张 Kintex-7 板的扩展 IO 上接了一块单颗 NAND 小板，使用
Macronix `MX30UF1G18AC-TI`，1.8 V、x8、TSOP48。先把读回数据与已有黄金
数据对上，再逐步加入缓存页读取、EDO 采样和 NAND→DDR 重叠搬运。

截至 **2026-10-14**，通过重复验证的最快配置为 **125 MHz、53.39 MB/s**。
新的 150 MHz 晚采样版本已经构建完成，停在实机验证前。

本页记录增量 NAND 实验。仓库现有 `fpga/build.tcl` 仍构建 XDMA/DDR 基线；
本次更新没有加入 NAND 实验 RTL 或可下载镜像。

## 实验路径与测速口径

数据路径是 **NAND → FPGA 页缓冲 → DDR3 → XDMA → Linux 校验**。
主机仍使用 MS-A2 原生 PCIe、Ubuntu 24.04.5 Persistent Live USB，内核
`7.0.0-31-generic`，Secure Boot 保持开启。

下面的速度来自 FPGA 对完整 NAND→DDR 请求的周期计数，分子只算每页
2048 bytes 的有效数据，包含命令、忙等待和 DDR 搬运时间。单位为十进制
MB/s；它与前面的 PCIe DMA MiB/s、RAM 盘文件读写速度分别统计。

当前 EDO 每两个控制时钟读取一个字节。表中的 MHz 是控制时钟频率，
不是每秒传输的字节数。

| 配置 | 字节周期 | 有效数据速度中位数 | 验证结果 |
| --- | ---: | ---: | --- |
| 此前 RB88 普通读取 | — | 27.073643 MB/s | 已实测 |
| 80 MHz EDO | 25 ns | 35.428934 MB/s | 原版 63° 相位通过 8192 次块读 |
| 88.889 MHz EDO | 22.5 ns | 39.071096 MB/s | 4096 次块读通过 |
| 100 MHz EDO | 20 ns | 43.566937 MB/s | 4096 次块读通过 |
| 125 MHz EDO | 16 ns | **53.393297 MB/s** | **4096 次块读通过** |

125 MHz 比此前 RB88 普通读取快约97.2%，比100 MHz EDO快约22.55%。
这组结果来自同一颗实物；150 MHz 尚没有通过的数据结果，不列入速度表。

## 125 MHz 到底验证了什么

采样相位为112.5°，延迟2.5 ns。4096次 EDO 全块读取，以及前后的
1次慢速、6次普通模式请求全部通过，共4103个请求。

- 覆盖 block 2 的64页，即 row 128–191；每页2048 bytes数据及64 bytes OOB。
- 4096次重复累计512 MiB有效数据；是同一组页的重复读取，不是整颗扫描。
- 中位速度53.393297 MB/s，最低/最高为53.392079 / 53.399735 MB/s。
- 原始数据、OOB、CRC、逐页/整块哈希及DDR预填充检查一致，BCH纠错数为0。
- U13板温为36.5–37.25°C；驱动清理和温度专用SRAM恢复通过。

每次读取前先给DDR目标区填入与期望数据不同的内容，再执行NAND读取，
避免把旧DDR数据当成新结果。归档保留原始样本和每个请求的完整校验记录，
没有为4096次重复分别保存一份相同raw文件。

## 150 MHz 的两次真实读错

150 MHz 使用13.333333 ns字节周期。第一次通过实现时序检查后，
实机读取仍然失败，因此构建通过不能代替数据比较。

| 采样相位 | 首次失败 | 原始结果 |
| --- | --- | --- |
| 67.5° / 1.25 ns | row 128、column 0，首个1-byte EDO请求 | `0x0D`，期望`0x4D`；DQ6一位错误 |
| 157.5° / 2.916667 ns | 首个完整2112-byte页读，首错在column 68 | `0x8F`，期望`0x9F`；全页96 bytes、102 bits错误 |

157.5°版本的1/2-byte请求先通过，完整页才失败。错误主要在DQ4和DQ6，
102个错误位都等于前一字节的对应位；整体字节移位比较不成立。
这支持部分DQ尚未稳定就被采样的方向，还不能据此确定颗粒的绝对频率上限。

两次测试都保留了第一次失败的raw数据，重试次数为0；完整页的CRC/BCH也
识别出异常，没有用纠错掩盖错误。失败后普通模式恢复读取通过，未进入连续
EDO测试。

## 新版 CE150：已构建，尚未上板

下一版保持150 MHz和每两拍一字节，将采样后移到225°，即4.166667 ns。
输入寄存器只在指定采样槽更新，并在中间一拍保持数据；采样令牌随后授权
shadow寄存器接收，再提交到页缓冲。CSR地址和写入检查也增加了一阶段流水。

构建复用了XDMA与多数辅助IP缓存，MIG及修改模块重新综合。Clock Wizard
实际选出的VCO为1050 MHz，参考输出200 MHz，主时钟和采样时钟均为150 MHz。

| 检查项 | CE150状态 |
| --- | --- |
| RTL回归 | 13项通过；11项本轮执行，2项按全部输入哈希复用 |
| 主机侧回归 | 11项通过 |
| 内部STA | setup WNS +0.015 ns，hold WHS +0.015 ns |
| 实现检查 | DRC Error 0，34条bus-skew约束通过 |
| 正常模式双角外部I/O | PASS |
| 完整EDO外部预算 | `NOT_QUALIFIED` |
| 实机下载与数据比较 | **`NOT_RUN`** |

构建时发现XDC解析器跳过了`for`循环，八对数据多周期约束没有进入DCP。
修复将约束放进真正执行的Tcl，从已有布线结果续签核，无需重综合或重布线。
最终检查实际数据setup/hold边沿，并验证CE控制路径仍正常计时、wait令牌
为0时shadow CE必为0。以后检查约束要看实际覆盖和边沿，不能只看源文件里
写了什么。

截至本次记录，测试已停在实机验证前。CE150的bitstream SHA-256为：


## 哪些优化已用上，还有哪些值得继续

缓存页读取使用`31h/3Fh`，EDO利用上一字节的数据窗口，页缓冲水位允许
NAND读取与DDR搬运重叠。这些已经进入当前实验，继续优化不能重复计算收益。

另外做了一版DDR尾部预取：最后一段数据完全复制后，提前发下一页缓存命令，
与旧页DDR写响应重叠。150 MHz协议仿真中，64页、B响应延迟0/5拍分别减少
0.1142% / 0.2363%耗时。它只完成离线验证，还不是实机提速结果；要隐藏更多
尾部，需要更宽的页缓冲读口或双缓冲，而不是依赖典型NAND忙等待来防止覆盖。

RE#已使用专用I/O输出寄存器，单纯再做IOB packing没有新增收益。
后续先验证CE150的数据窗口，再决定是否扫描相位、提高时钟或调整缓冲架构。

## 手册、温度和内核日志

[Macronix Rev.1.2手册](https://www.macronix.com/Lists/Datasheet/Attachments/8457/MX30UF1G18AC,%201.8V,%201Gb,%20v1.2.pdf)
给出`tRC ≥ 25 ns`、`tRP ≥ 12 ns`、`tREH ≥ 10 ns`、`tREA ≤ 22 ns`。
x8总线按25 ns换算为40 MB/s原始字节速率；只扣除页内OOB后为38.788 MB/s，
还没扣忙等待、命令和搬运。它与上表有效请求吞吐的口径不同。

125/150 MHz EDO周期与脉宽低于手册最小值，是本实物的超频实验。
完整EDO外部预算仍未合格，室温重复读取通过不等于所有电压、温度和布线
条件下的保证。当前颗粒使用异步接口，不能只改控制器就开启NV-DDR或DQS。

这组NAND镜像持续监测U13板温：取得有效且新鲜的温度前禁止START；达到
60°C，或读数无效、过期、I²C故障时锁停实验，接口回到空闲或高阻，测温继续。
恢复实验需要明确操作。JTAG可用时，主机恢复温度专用SRAM并核对配置；本轮
记录包含实际清理回退，不包含人为加热到阈值的实机验证。

驱动载入及NAND读取窗口没有新增相关内核错误；PCIe端点移除时仍记录到
`amd_iommu_release_device`警告。数据通过和清理完成不等于整个生命周期
完全没有警告。
